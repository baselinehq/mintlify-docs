Depot accelerates container builds, GitHub Actions runners, and agent sandboxes,
and its API reports usage as billed minutes and stored GB per product and project
rather than as dollars. Depot has no vCPU or credits dimension, so CostGraph
reconstructs cost from those minutes and GB at Depot's published (or your
negotiated) per-minute rates.

CostGraph reads Depot as **FOCUS 1.2** records at a grain of one usage-cost record
per product (build, runner, sandbox, storage) per project or repo per window,
pulled from `UsageService.GetUsage` and `ListProjectUsage` on api.depot.dev.

## Let CostGraph pull

1. Open **Settings -> Integrations** and pick **Depot**.
2. Name the connection and pick the tenant these charges belong to.
3. Fill in the values the form asks for. It lists exactly the keys Depot needs and
   explains each one. You create an organization token under **Organization
   settings -> API tokens**; it reads usage history via
   `depot.core.v1.UsageService` and is sent as an `Authorization: Bearer` token.
4. Select **Connect**.

CostGraph verifies the credentials with a short fetch before saving, so a wrong
value or a missing permission fails while you are still on the form.

### Credentials

| Variable | Required | Secret | Description |
| --- | --- | --- | --- |
| `DEPOT_API_TOKEN` | yes | yes | Depot organization token (Organization settings -> API tokens). Reads usage history via `depot.core.v1.UsageService`. Sent as an `Authorization: Bearer` token. |
| `DEPOT_ORGANIZATION_ID` | no | no | Organization identifier used as the billing account id label. The token is already scoped to one organization; when unset the record uses `depot`. |
| `DEPOT_BUILD_MINUTE_RATE` | no | no | USD per container-build minute used to reconstruct cost (the API reports billed minutes, not dollars). Defaults to Depot's published 16 vCPU rate `0.04`. |
| `DEPOT_RUNNER_MINUTE_RATE` | no | no | USD per GitHub Actions runner minute. Defaults to `0.008` (4 vCPU published rate). |
| `DEPOT_SANDBOX_MINUTE_RATE` | no | no | USD per agent-sandbox minute. Defaults to `0.006` (2 vCPU published rate). |
| `DEPOT_STORAGE_GB_RATE` | no | no | USD per cache/registry GB-month. Defaults to Depot's published `0.20`. |

<Note>
Cost is an estimate: Depot exposes billed minutes and GB, not dollars, so
CostGraph rates them at the published defaults unless you override with the
`DEPOT_*_RATE` variables. Plan-included and negotiated minutes are not reflected,
so set the rate overrides to match your contract for an accurate figure.
Credentials are encrypted at rest and used only to read usage history. Revoke the
token in Depot at any time and the connection stops; nothing else is affected.
</Note>

## Push it yourself

Send the cost report to CostGraph as FOCUS records instead. [Push FOCUS data](/costgraph/integrations/focus-push) covers the connection id,
the `focus:write` key, and the request shape.

## Value signal

Depot's whole pitch is cache acceleration, so the moat is proving it: minutes
saved by the cache next to minutes actually billed says whether the acceleration
is earning its cost. CostGraph carries these as FOCUS extensions so a build spend
can be judged valid or wasteful, not just reported.

| Extension | Signals |
| --- | --- |
| `x_MinutesSaved` / `x_MinutesBilled` | Cache-avoided minutes against billed minutes per project. A high saved-to-billed ratio is the cache paying for itself; a low one is acceleration you pay for but barely use. |
| `x_BuildDurationSeconds` | Per-project container-build compute-seconds, the underlying build workload behind the spend. |
| `x_LayerCacheSizeGb` | Per-project layer-cache size, so a large cache with few builds is stored bytes going unused. |
| `x_BuildCount` | Builds run in the window, for sizing per-build cost. |
| `x_JobCount` / `x_MinutesElapsed` | Per-repo GitHub Actions runner jobs and wall-clock minutes, so billed runner minutes can be checked against elapsed time. |
| `x_SandboxesCount` | Agent sandboxes run, splitting sandbox minutes from build and runner minutes. |
| `x_StorageType` | Whether the stored GB is cache or registry, so storage spend stays attributable. |

## What CostGraph does with it

Records land as raw billing rows, are normalised into line items, and roll up into
daily cost. From there Depot spend appears in Cost Overview and in anomaly
detection alongside every other provider, with the value-signal extensions
available to flag caches that are not paying for their acceleration.
