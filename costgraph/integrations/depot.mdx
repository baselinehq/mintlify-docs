Depot accelerates container builds, GitHub Actions runners, and agent sandboxes,
and reports usage per product and project.

CostGraph reads Depot as **FOCUS 1.2** records at a grain of one record per product
(build, runner, sandbox, storage) per project per day.

## Choose how the data reaches us

<CardGroup cols={2}>
  <Card title="CostGraph pulls it" icon="cloud-arrow-down">

  </Card>
  <Card title="You push it" icon="cloud-arrow-up">

## Create an organization token

1. In the Depot dashboard, open **Organization -> Settings**.
2. Copy the **Organization ID** from the sidebar if you want it as the billing
   account label in CostGraph. The token is already scoped to this organization;
   the id is only a label.
3. Scroll to **API Tokens**, enter a description, and click **Create token**.
4. Copy the token once. Depot will not show it again.

<Note>
Use an **organization** token, not a user or project token. CostGraph sends it as
an `Authorization: Bearer` token to `depot.core.v1.UsageService`. The token can
also create builds and manage projects in Depot, so treat it as a secret and
revoke it if you rotate credentials.
</Note>

## Let CostGraph pull

1. In CostGraph, open **Settings -> Integrations**
   (`/settings/account/integrations`) and pick **Depot**.
2. Name the connection and pick the tenant these charges belong to.
3. Paste the organization token. Optionally set the organization id and any rate
   overrides. The form lists every key and whether it is required.
4. Select **Connect**.

CostGraph verifies the credentials with a short fetch before saving, so a wrong
value fails while you are still on the form.

### Credentials

| Variable | Required | Secret | Description |
| --- | --- | --- | --- |
| `DEPOT_API_TOKEN` | yes | yes | Organization token from **Organization -> Settings -> API Tokens**. |
| `DEPOT_ORGANIZATION_ID` | no | no | Organization id from the Depot sidebar, used as the billing account label. When unset the record uses `depot`. |
| `DEPOT_BUILD_MINUTE_RATE` | no | no | USD per container-build minute. Defaults to Depot's published 16 vCPU rate `0.04`. |
| `DEPOT_RUNNER_MINUTE_RATE` | no | no | USD per GitHub Actions runner minute. Defaults to Depot's published default 2 vCPU rate `0.004`. |
| `DEPOT_SANDBOX_MINUTE_RATE` | no | no | USD per agent-sandbox minute. Defaults to Depot's published rate `0.01`. |
| `DEPOT_STORAGE_GB_RATE` | no | no | USD per cache/registry GB-month. Defaults to Depot's published `0.20`. |

<Note>
Cost is an estimate: Depot exposes billed minutes and GB, not dollars, so
CostGraph rates them at the published defaults unless you override with the
`DEPOT_*_RATE` variables. Plan-included minutes and negotiated pricing are not
subtracted, so set the overrides to match your contract if you need the figure
to line up with the Stripe invoice. Credentials are encrypted at rest and used
only to read usage history. Revoke the token in Depot at any time and the
connection stops; nothing else is affected.
</Note>

## What the usage numbers mean

Depot's **Organization -> Settings -> Usage** (and **Organization -> Usage**)
tracks the same meters CostGraph pulls: container-build minutes, GitHub Actions
minutes, cache GB, and agent-sandbox minutes.

<Frame caption="Depot current usage. CostGraph maps these meters into FOCUS records; it reconstructs dollars from the minutes and GB.">
  <img src="/images/integrations/depot-current-usage.png" alt="Depot current usage showing container build minutes, GitHub Actions minutes, Depot CI minutes, and cache storage for the month" />
</Frame>

CostGraph maps **container builds**, **GitHub Actions runners**, **cache and
registry storage**, and **agent sandboxes**. **Depot CI** minutes (billed per
vCPU-second on Depot's side) are visible in this dashboard but are not a
separate CostGraph product line yet.

## Push it yourself

Send the charges to CostGraph as FOCUS records instead. [Push FOCUS data](/costgraph/integrations/focus-push) covers the connection id,
the `focus:write` key, and the request shape.

## What CostGraph does with it

Records land as raw billing rows, are normalised into line items, and roll up into
daily cost. From there Depot spend appears in Cost Overview and in anomaly
detection alongside every other provider, so you can see whether the build cache
is earning its cost.
