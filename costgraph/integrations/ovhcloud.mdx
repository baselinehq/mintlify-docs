OVHcloud bills monthly across every product, so spend is attributed per bill line item with Public Cloud usage carried per project.

CostGraph reads OVHcloud as **FOCUS 1.2** records at a grain of bill line item.

## Choose how the data reaches us

## Create a service account

CostGraph authenticates with an OVHcloud **OAuth2 service account**, which uses the
client-credentials flow. The id and secret do not expire.

1. In the [OVHcloud Control Panel](https://www.ovh.com/manager/), open
   **Identity, Security & Operations -> Identities -> Service account**.
2. Select **Add a service account**, give it a name and a description
   (for example `costgraph-billing`), then **Create**.
3. Copy both values from the confirmation window: the **service account name** is the
   client id, the **password** is the client secret.

<Warning>
The secret is shown once and cannot be retrieved or regenerated afterwards. Copy it
before closing the window; if you lose it, delete the service account and create
another.
</Warning>

The client id carries the API region as its prefix - `EU.`, `CA.` or `US.` - and it
must match the region your OVHcloud account lives in. A client id from the wrong
region fails to authenticate with `invalid_client`.

## Required accesses

Service accounts start with no rights. Attach an IAM policy
(**Identity, Security & Operations -> Identities -> Policies**) that gives yours read
access to billing and, if you run Public Cloud, to project usage:

| API call | IAM action | Why CostGraph needs it |
|----------|------------|------------------------|
| `GET /me` | `account:apiovh:me/get` | Identify the billing account |
| `GET /me/bill`, `GET /me/bill/{id}` and its details | billing read | Read invoices and their line items |
| `GET /cloud/project` | `publicCloudProject:apiovh:get` | List Public Cloud projects |
| `GET /cloud/project/{id}/usage/current` | `publicCloudProject:apiovh:usage/current/get` | Read the running month before it is invoiced |

The quickest route is OVHcloud's managed **Global billingAccount** permission group,
which carries billing rights across every product. The IAM action a given route needs
is shown on its **IAM actions** line in the
[OVHcloud API console](https://api.ovh.com/console/).

## Let CostGraph pull

1. Open **Settings -> Integrations** and pick **OVHcloud**.
2. Name the connection and pick the tenant these charges belong to.
3. Paste the client id and client secret. Optionally set a Public Cloud project id to
   scope the running month to one project; leave it empty and every project the
   service account can see is included.
4. Select **Connect**.

CostGraph verifies the credentials with a short fetch before saving, so a wrong
value or a missing permission fails while you are still on the form. An account with
no recent invoice still connects: CostGraph reads the billing account from `/me`.

<Note>
Credentials are encrypted at rest and used only to read billing data. Revoke them in
OVHcloud at any time and the connection stops; nothing else is affected.
</Note>

## Push it yourself

Send the charges to CostGraph as FOCUS records instead. [Push FOCUS data](/costgraph/integrations/focus-push) covers the connection id,
the `focus:write` key, and the request shape.

## Run the exporter

Rather than build that request yourself, run our exporter. It reads OVHcloud on a
schedule and pushes the records for you, wherever you want to run it: a container, a
Kubernetes `CronJob`, or a binary on a machine you already have.

```bash
focus-exporter --provider ovhcloud --sink costgraph
```

Your OVHcloud credential stays where you put it, and only the finished FOCUS records
reach CostGraph. [Run the exporter](/costgraph/integrations/exporter) covers the three
ways to run it and the variables it reads.

## What CostGraph does with it

Records land as raw billing rows, are normalised into line items, and roll up into
daily cost. From there OVHcloud spend appears in Cost Overview and in anomaly
detection alongside every other provider.
