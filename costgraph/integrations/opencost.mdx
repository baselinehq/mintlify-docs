---
title: OpenCost API
description: "Read Kubernetes allocation from tools that already speak OpenCost"
---

CostGraph serves the OpenCost allocation API. Tools built against OpenCost, such
as Grafana dashboards, cost scrapers, and CI budget checks, read CostGraph by
changing the address they point at.

The response is the allocation format OpenCost defines, field for field. You
don't map or rename anything.

## Before you begin

- An API key with the `operator:read` scope. Create one in **Settings > API keys**.
- At least one connected Kubernetes cluster.

## Endpoint

Point your client at the base URL and send the key as a header.

```text
https://api.costgraph.ai/api/v1/tenant/opencost
X-API-Key: bl_your_key
```

CostGraph serves these routes:

```text
GET /allocation
GET /allocation/compute
GET /allocation/summary
GET /allocation/compute/summary
GET /assets
GET /cloudCost
```

`/allocation` and `/allocation/compute` are the same query, as they are in
OpenCost. The summary routes return the same data in OpenCost's lighter summary
shape.

A client that lets you set a base URL needs no other change. A client that
hardcodes `http://opencost:9003` needs that value replaced.

## Query parameters

`window` is required. Everything else is optional.

| Parameter | Type | Description |
| --- | --- | --- |
| `window` | string | The period to report. Accepts a duration (`24h`, `7d`), `today`, `yesterday`, or a comma-separated pair of RFC3339 timestamps. |
| `aggregate` | string | A comma-separated list of properties to group by. Omit it to get one allocation per container. |
| `step` | string | The duration of each returned set. Defaults to the whole window. |
| `accumulate` | boolean | Collapse the range into a single set. |
| `includeIdle` | boolean | Return unallocated cluster cost as its own `__idle__` allocation. Off by default. |
| `shareIdle` | boolean | Distribute idle across the other allocations instead, weighted by what each one consumes. |

`aggregate` accepts `cluster`, `node`, `namespace`, `controller`, `pod`, and
`container`. Names are composed the way OpenCost composes them: the properties
you asked for, joined by `/`. A controller is rendered as its kind and name, so
`aggregate=controller` returns `deployment:api`. A property with no value
returns `__unallocated__`.

## Response

The response is a `data` array holding one allocation set per step, each keyed
by allocation name.

```json
{
  "code": 200,
  "data": [
    {
      "kube-system": {
        "name": "kube-system",
        "properties": { "cluster": "prod", "namespace": "kube-system" },
        "window": { "start": "2026-09-01T00:00:00Z", "end": "2026-09-02T00:00:00Z" },
        "cpuCoreHours": 24,
        "cpuCost": 1.5,
        "cpuEfficiency": 0.5,
        "ramByteHours": 2147483648,
        "ramCost": 0.5,
        "totalCost": 2,
        "totalEfficiency": 0.5
      }
    }
  ]
}
```

## Assets

`GET /assets` returns the nodes and disks billed over the window, keyed the way
OpenCost keys them. It takes `window` and `step`.

A node carries its instance type, the cores and bytes it offered over the
window, and its cost split across CPU and memory. The two parts add back to the
node's bill. A disk carries its provisioned bytes and storage class.

Load balancers aren't reported.

## Cloud cost

`GET /cloudCost` returns what your vendors billed you, as opposed to how
CostGraph allocated it. It takes `window`, `aggregate`, `step`, and
`accumulate`.

`aggregate` accepts `invoiceEntityID`, `accountID`, `regionID`,
`availabilityZone`, `provider`, `providerID`, `category`, and `service`. It
defaults to `provider,service`.

Every vendor CostGraph ingests a bill for appears here, SaaS and cloud alike, so
aggregating by `provider` returns Datadog and GitHub next to AWS. Costs come
from the bill, so they exclude CostGraph's own allocation of that spend.

`kubernetesPercent` reports `0`. Filling it in means matching each billed
resource back to a Kubernetes node, which CostGraph doesn't resolve today.

## Cost model

CostGraph bills CPU and memory on the greater of a container's request and its
usage, which is what the OpenCost specification defines as workload cost. A
container that reserves more than it uses is billed for the reservation.

Idle is the part of a node's bill that no container accounts for, measured per
node so an over-committed node can't offset an empty one. Ask for it with
`includeIdle=true` and workload cost plus idle equals the cluster bill.

## What CostGraph doesn't serve

CostGraph implements the allocation, asset, and cloud cost queries. The
following parts of the OpenCost API return no data.

| Parameter or route | Behavior |
| --- | --- |
| `filter` | Ignored. Aggregate to the grain you want instead. |
| `idleByNode` | Accepted and ignored. Idle is reported for the cluster. |
| `/customCost/total`, `/customCost/timeseries` | Not served. SaaS spend is reported by `/cloudCost` instead. |

### Why SaaS spend isn't on customCost

OpenCost splits its API because it ingests cloud bills and third-party costs
through two different pipelines. CostGraph ingests every vendor the same way,
into one FOCUS dataset. Splitting the response again would mean inventing a
boundary and classifying each new vendor against it, so `/cloudCost` reports
both.

Allocation covers CPU and memory. Storage, network, and load balancer cost
aren't part of the response, so `pvCost`, `networkCost`, and
`loadBalancerCost` report `0`.

## Limits

A request that asks for more than 10,000 steps, such as a 30 day window at a one
second step, returns `400`. A query returning more than 200,000 allocations
returns `400`. Widen the step or narrow the window.
