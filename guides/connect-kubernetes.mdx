---
title: Connect EKS, GKE, or AKS
description: "Install the operator on a managed Kubernetes cluster"
---

Connecting a managed cluster is the same Helm install as any cluster, once your `kubectl` context points at it.

## Get the cluster context

<Tabs>
  <Tab title="EKS">
    ```bash
    aws eks update-kubeconfig --name <cluster> --region <region>
    ```
  </Tab>
  <Tab title="GKE">
    ```bash
    gcloud container clusters get-credentials <cluster> --region <region>
    ```
  </Tab>
  <Tab title="AKS">
    ```bash
    az aks get-credentials --name <cluster> --resource-group <group>
    ```
  </Tab>
</Tabs>

## Install the operator

```bash
helm repo add costgraph http://charts.costgraph.ai/
helm repo update
helm install costgraph-operator costgraph/costgraph-operator \
  --namespace costgraph --create-namespace \
  --set global.clusterName=<cluster> \
  --set global.apiKey=<api-key>
```

See the [operator reference](/costgraph/operator/overview) for production options like `existingSecret`.

## Clusters without nodes you manage

The operator collects host and container metrics with node-exporter and cAdvisor, which run as DaemonSets and need node-level access. Those metrics are limited where you don't manage the nodes:

- GKE Autopilot restricts privileged DaemonSets and host access.
- EKS or AKS running only on Fargate or virtual nodes has nowhere to schedule the DaemonSets.

On these clusters the operator still exports your cluster inventory and Kubernetes object metrics. Run on standard node pools for full host and container metrics.
