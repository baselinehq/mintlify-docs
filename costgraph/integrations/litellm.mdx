LiteLLM is a self-hosted gateway that fronts many LLM providers behind one proxy
and tracks the spend of every request it routes. That spend is LiteLLM's own
computed figure, so CostGraph reads real dollars here rather than reconstructing
them from tokens.

CostGraph reads LiteLLM as **FOCUS 1.2** records at a grain of one record per day
per model per virtual key, read from `GET /spend/logs` on your own proxy
deployment.

## Let CostGraph pull

1. Open **Settings -> Integrations** and pick **LiteLLM**.
2. Name the connection and pick the tenant this spend belongs to.
3. Fill in the values the form asks for. It lists exactly the keys LiteLLM needs
   and explains each one. You supply the base URL of your LiteLLM proxy and its
   master key (`sk-...`); the master key reads spend across all virtual keys via
   `GET /spend/logs` and is sent as an `Authorization: Bearer` token.
4. Select **Connect**.

CostGraph verifies the credentials with a short fetch before saving, so a wrong
value or a missing permission fails while you are still on the form.

### Credentials

| Variable | Required | Secret | Description |
| --- | --- | --- | --- |
| `LITELLM_BASE_URL` | yes | no | Base URL of your LiteLLM proxy, e.g. `https://litellm.mycompany.com`. The adapter reads spend from this deployment. |
| `LITELLM_MASTER_KEY` | yes | yes | LiteLLM proxy master key (`sk-...`). Sent as an `Authorization: Bearer` token; required to read spend across all virtual keys. |

<Note>
LiteLLM computes the spend of each request it routes, so cost here is a real
tracked figure, not an estimate. The dollars are only as complete as your proxy's
own model-pricing configuration. Credentials are encrypted at rest and used only
to read spend logs. Revoke or rotate the master key in LiteLLM at any time and the
connection stops; nothing else is affected.
</Note>

## Push it yourself

Send the cost report to CostGraph as FOCUS records instead. [Push FOCUS data](/costgraph/integrations/focus-push) covers the connection id,
the `focus:write` key, and the request shape.

## Value signal

The point of a shared gateway is attributing spend back to who spent it. CostGraph
sets the sub-account to the virtual key (falling back to the team) and carries the
token mix, request volume, and every identity dimension LiteLLM records as FOCUS
extensions, so a cost can be attributed and judged, not just totalled.

| Extension | Signals |
| --- | --- |
| `x_PromptTokens` / `x_CompletionTokens` | The input against output token split behind the spend, so prompt-heavy and generation-heavy usage are distinguishable. |
| `x_ApiRequests` | Requests in the day for the model and key, for sizing per-request cost. |
| `x_UpstreamProvider` | The provider LiteLLM routed to (OpenAI, Anthropic, ...), so spend stays attributable across the models behind the gateway. |
| `x_KeyAlias` | The virtual key's human alias, so a key id maps to a recognisable owner. |
| `x_TeamId` / `x_UserId` / `x_EndUser` | The team, internal user, and end user tied to the spend, for attribution down to who drove the cost. |

## What CostGraph does with it

Records land as raw billing rows, are normalised into line items, and roll up into
daily cost. From there LiteLLM spend appears in Cost Overview and in anomaly
detection alongside every other provider, with the value-signal extensions
available to attribute spend to the key, team, and user behind it.
