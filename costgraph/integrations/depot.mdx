Depot accelerates container builds, GitHub Actions runners, and agent sandboxes,
and reports usage per product and project.

CostGraph reads Depot as **FOCUS 1.2** records at a grain of one record per product
(build, runner, sandbox, storage) per project per day.

## Choose how the data reaches us

<CardGroup cols={2}>
  <Card title="CostGraph pulls it" icon="cloud-arrow-down">
    You supply read-only credentials and we call Depot once a day. Nothing to run.
  </Card>
  <Card title="You push it" icon="cloud-arrow-up">
    You send us FOCUS records over the API. Credentials never leave your infrastructure.
  </Card>
</CardGroup>

## Before you begin

- In the Depot dashboard, go to **Organization settings > API tokens** and create an
  organization token. A project token reads one project and can't see org-wide usage.

## Let CostGraph pull

1. Open **Settings > Integrations** and pick **Depot**.
2. Name the connection and pick the tenant these charges belong to.
3. Enter the values you copied. The form lists what Depot needs and marks the
   optional ones.
4. Select **Connect**.

CostGraph verifies the credentials with a short fetch before saving, so a wrong
value or a missing permission fails while you are still on the form.

<Note>
Credentials are encrypted at rest and used only to read billing data. Revoke them in
Depot at any time and the connection stops; nothing else is affected.
</Note>

## Push it yourself

Send the charges to CostGraph as FOCUS records instead. [Push FOCUS data](/costgraph/integrations/focus-push) covers the connection id,
the `focus:write` key, and the request shape.

## Run the exporter

Rather than build that request yourself, run our exporter. It reads Depot on a
schedule and pushes the records for you, wherever you want to run it: a container, a
Kubernetes `CronJob`, or a binary on a machine you already have.

```bash
focus-exporter --provider depot --sink costgraph
```

Your Depot credential stays where you put it, and only the finished FOCUS records
reach CostGraph. [Run the exporter](/costgraph/integrations/exporter) covers the three
ways to run it and the variables it reads.

## What CostGraph does with it

Records land as raw billing rows, are normalised into line items, and roll up into
daily cost. From there Depot spend appears in Cost Overview and in anomaly
detection alongside every other provider, so you can see whether the build cache
is earning its cost.
